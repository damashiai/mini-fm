# Mini-FM

> A high-performance audio streaming backend demonstrating secure content delivery and binary stream handling.

Mini-FM is a full-stack application designed to showcase advanced backend engineering principles. It implements a secure proxy server to handle byte-range requests, enabling efficient audio seeking and partial content delivery (HTTP 206) without exposing the underlying storage infrastructure to the client.

## Key Technical Features

* **Byte-Range Streaming (HTTP 206):** Implements manual handling of HTTP `Range` headers. The server parses the requested byte intervals and fetches only the necessary chunks from cloud storage, allowing for instant seeking and reduced bandwidth consumption.
* **Secure Proxy Architecture:** Utilizes a "Bouncer" pattern where the Flask backend acts as an intermediary. This ensures that direct storage URLs are never exposed to the client, allowing for strict access control and data sanitization before delivery.
* **Row Level Security (RLS):** Integrates with Supabase's RLS policies to enforce database-level security. Write and delete operations are restricted by policy, ensuring data integrity even if API keys are compromised.
* **MIME-Type Intelligence:** dynamically detects and serves correct `Content-Type` headers for various audio formats (MP3, M4A), ensuring cross-browser compatibility.

## Architecture & Tech Stack

* **Backend:** Python (Flask) running on Gunicorn for production-grade concurrency.
* **Infrastructure:** Containerized using Docker and Docker Compose.
* **Database & Storage:** Supabase (PostgreSQL for metadata, S3-compatible storage for binary files).
* **Frontend:** HTML5 Audio API, Tailwind CSS, and Jinja2 templating.

## Supabase Configuration

To run this project, you must set up a Supabase project. Follow these steps:

1.  **Create Project:**
    Log in to [Supabase](https://supabase.com) and create a new project.

2.  **Database Setup (SQL):**
    Go to the **SQL Editor** in your dashboard and run the following query to create the metadata table:
    ```sql
    CREATE TABLE audio_files (
        id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
        title TEXT NOT NULL,
        artist TEXT NOT NULL,
        file_path TEXT NOT NULL,
        album_art_url TEXT,
        created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now())
    );
    ```

3.  **Storage Setup:**
    * Go to **Storage** and create a new public bucket named `audio_files`.
    * **Important:** You must add RLS Policies to allow uploads and deletions.
    * Under **Configuration > Policies**, create a new policy for the `audio_files` bucket allowing `INSERT` and `DELETE` operations for the `anon` role.

4.  **Credentials:**
    Go to **Project Settings > API**. You will need the `Project URL` and the `anon public` key for your `.env` file.
    
## Installation & Setup

You can run the application using Docker (recommended) or a local Python environment.

### Option 1: Docker (Recommended)

1.  **Clone the repository:**
    ```bash
    git clone [https://github.com/damashiai/mini-fm.git](https://github.com/damashiai/mini-fm.git)
    cd mini-fm
    ```

2.  **Configure Environment:**
    Create a `.env` file in the root directory with your credentials:
    ```env
    SUPABASE_URL="your_supabase_url_here"
    SUPABASE_KEY="your_supabase_anon_key_here"
    ENABLE_WRITE_OPERATIONS=True
    ```

3.  **Build and Run:**
    ```bash
    docker-compose up --build
    ```
    The application will be accessible at `http://localhost:5000`.

### Option 2: Manual Installation

1.  **Set up Virtual Environment:**
    ```bash
    python -m venv venv
    # Linux/Mac:
    source venv/bin/activate
    # Windows:
    venv\Scripts\activate
    ```

2.  **Install Dependencies:**
    ```bash
    pip install -r requirements.txt
    ```

3.  **Run Application:**
    ```bash
    python app.py
    ```

## Configuration & Security

* **Feature Flags:** The application supports environment-based feature flagging. Setting `ENABLE_WRITE_OPERATIONS=False` in the `.env` file will disable all upload and delete endpoints at the routing level, making the instance read-only.
* **Input Sanitization:** All file uploads undergo strict filename sanitization to prevent directory traversal attacks and URL encoding issues.
